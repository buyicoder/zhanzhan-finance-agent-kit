# Agent 独立重扫与盲测协议

## 目标

测试 Agent 能否在没有人工逐条纠偏的情况下，从原件独立产生稳定事实、正确关系和可审核表格。测试自主判断能力，不以复刻旧表为任务，也不以匹配率最大化为目标。

## 一、隔离答案

- 新建实验表/实验批次，不覆盖现有满意结果。
- 冻结文件清单、排序、对象 Token、SHA 和测试批次 ID。
- Agent 可读取原件、来源元数据和同批已处理事实；禁止读取旧分类、旧关系、旧系统判断、人工审核意见、历史纠错报告和旧目标表答案。
- 旧结果只在一批完成后由评估器读取，用作差异审计，不自动视为绝对真值。
- 发现旧结果可能错误时，必须提交原件页码和反证，不能为了对齐而改答案。

## 二、双模式测试

### 历史半批

- 按公司分层并在各公司内部按稳定时间/Token排序后切前半，避免一家公司占满前半。
- 机器批量完成枚举、下载、格式识别、SHA去重、文本/OCR、相似组和候选召回。
- Agent 按独立内容组分析；所有高价值、签章、金额、矛盾、低置信和代表性对象必须视觉把关。
- 批量只节约准备成本，不降低最终事实与关系硬门。

### 流式半批

- 按冻结顺序一次释放一个对象，禁止偷看未来文件。
- 每个对象完成观察、事实、关系、动作、写入和回验后，才释放下一个。
- 允许并行下载/OCR已释放对象，但生产写入按对象/稳定键串行提交。
- 后续文件可以补强或纠正旧事实，但必须保留变更历史和纠错原因。

## 三、首轮执行

先做100对象双模式试验：50历史分层批量、50逐文件流式。通过后再扩至500和全量。不要用小样本调到完美后继续泄漏答案；每轮使用未见过的冻结对象。

每个对象都要生成 decision manifest，并运行：

```bash
python3 scripts/validate_decision.py path/to/decision.json
```

## 四、评分

按业务价值评分，不用分类准确率作为主指标：

1. 事实召回：原件可证实的关键业务事实提取率；
2. 事实精确：是否伪造金额、日期、主体、签章或验收；
3. 事实身份：副本不重复、一文件多事实正确拆分、版本正确归并；
4. 关系精确：确认关系通过主体/方向/项目/时间/额度硬门；
5. 拒绝能力：外部项目链、金额单键、错误角色和模板是否被主动排除；
6. 歧义诚实：多候选、确认缺失、证据不足、业务不适用是否表达准确；
7. 多表完整：事实驱动的目标表和快捷方式是否完整；
8. 工程质量：fresh-read、幂等、人工字段保护、回滚和断点续跑；
9. 自主性：每次人工介入次数、介入原因和介入后影响记录数。

严重错误单独计数：伪造关键事实、主体/方向不可能仍确认、候选伪装确认、副本重复计额、非购销进入经营利润、覆盖人工字段。严重错误不能被高召回率抵消。

## 五、一次到位的含义

“一步到位”指首次独立运行直接使用完整方法论和生产门禁，不指跳过试验门或承诺零错误。必须保留原始首跑结果，禁止在看到旧答案后悄悄重跑覆盖。输出三层结果：

- `first_pass`：Agent完全独立的原始能力；
- `self_corrections`：Agent通过反向审计自行发现并纠正；
- `gold_comparison`：批次结束后与旧结果及人工抽查比较。

只有这样才能知道Agent真正能做到什么，而不是再次得到一个被人工教到满意的结果。

## 六、停止与重开

自动运行可在高推进队列为空、所有未决项有明确原因、工程门禁通过时停止。出现新文件、人工补件或新审核口径时，用稳定事实 ID 增量重开，不全量推倒重来。
