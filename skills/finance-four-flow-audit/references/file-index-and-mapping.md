# 文件索引、分类与映射

## 文件对象

文件索引一行代表一个可独立定位的原始或派生文件对象。群文件、图片、对象库历史文件、压缩包成员、切割出的单笔回单分别登记。重发时保留来源消息，但不得因此重复创建业务事实。派生对象必须记录父文件、页码或成员路径和内容哈希。

## 三类标签

- 技术格式只描述 PDF、Excel、图片、压缩包等载体。
- 一级业务标签描述银行流水、回单、发票、合同、货物流、招投标、截图等核心作用，可多选。
- 专业标签描述单笔付款回单、采购合同、验收单、红字发票等细类。

复合文件保留一个原文件索引，同时建立多个专业记录；只有需要独立下载、审核或流转时才生成派生文件。已分类不等于处理完成。

## 主体归属

按统一社会信用代码、税号、账号、法定名称、已确认历史名称、来源位置、文件名、上下文的顺序判断。来源群只保留为来源，不得推翻原件主体。信用代码相同的新旧名称归并到同一法人键，同时保留票面原名。

## 映射语法

中文 `【键=值】` 与英文 `[键=值]` 等价；`回单` 与大写 `HD` 等价。映射可出现在文件名或与图片/文件同一消息的伴随文字中，不要求动作词。常用键包括：

- `合同` / `HT`
- `回单` / `HD`
- `流水`
- `发票`
- `项目`
- `货物流` / `验收` / `签收`

多个映射同时出现表示证据同时指向多个对象，并形成对象之间的强关系候选。必须保存原文件名、原伴随文字、解析键值、来源、采用状态和判断依据。

## 映射采用规则

映射是强信号，不是绝对命令。先精确搜索映射对象，再核对主体、角色、方向、金额、日期和原件内容：

- 唯一命中且无硬冲突：采用并建立或纠正关系。
- 多候选：逐个读取原件，不能任选。
- 未找到：保留待补对象，不编造记录。
- 与原件硬冲突：记录冲突并提交人工确认。

新回单纠正已有流水关联合同时，保留原流水事实和全部旧证据，只更新合同关系、标记错误候选被排除，并级联重算项目和审核表。

## 写入索引前检查

必须确认：原件已读、文件身份、重发/版本/派生关系、是否复合、全部标签、专业集合去向、法人依据、映射和线索、标签依据、冲突缺口。
